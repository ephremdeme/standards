- v0.1.24 — `bin/dispatch-deepseek`: a committed `.deepseek-lanes` overrides `.no-deepseek` for the lane branches it names (exchange D-161: DeepSeek implements named Go-port lanes in the exchange). Format: empty and `#` lines ignored, every other line exactly `<branch> D-<digits>` (one space, the branch in task-lint's grammar, no trailing space, no CR). It is read only from the TASK's `Base:` commit (never the worktree, the lane HEAD or the primary checkout), validated whole first (`refused — .deepseek-lanes line <n> is not '<branch> D-<number>'`, `refused — .deepseek-lanes lists <branch> more than once`, each refusing every lane of a `.no-deepseek` repo, listed or not), matched by exact string equality with the TASK's `Branch:`, and honoured only after task-lint and when Base is an ancestor of a branch head that `git ls-remote origin` reports (`refused — .deepseek-lanes is read from Base <base>, which no branch of origin contains`; a failing or empty ls-remote refused on its own; a hand-made `refs/remotes/` ref proves nothing). `GIT_NO_REPLACE_OBJECTS=1` is exported, and a `refs/replace/` ref, an `info/grafts` file or a `shallow` file in the common git dir refuses the override, each with its own message; revoking a lane means removing its line AND re-cutting or pruning its worktree (the listing is read at the lane's Base); an unlisted lane, or one whose TASK cannot be an override, keeps `refused — this repo never sends code to DeepSeek`, and every other refusal (admin surface, `Risk: HIGH` without `DISPATCH_ALLOW_HIGH=1`, task-lint, workspace trust, a dispatcher inside the worktree) still applies. - v0.1.23 — `bin/local-mutants`: `--resume <out-dir>` (exchange D-154: a lost 3-hour run was redone from scratch), in either order with `--tests`, each at most once. It resumes an earlier run's outcome directory, which now also holds `resume.txt` (`clone=`, `base=`, `head=`), with `-o <out-dir> --iterate` on the run only. It is refused (exit 2) when the directory is not this clone's (`… is not an outcome directory of local-mutants`, `… of another clone`), and with "the base or HEAD changed since that run; start a new one" when the fresh diff is not byte-identical, base or HEAD differ, or the fresh `--list` differs from `list.txt`. `cargo mutants --help` does not say whether iterated outcome files are cumulative, so caught and unviable are counted as the union of every earlier file and the new run's (kept in `<out-dir>/union/`, rebuilt from `union/<kind>.txt`, `union/<kind>.prev` and `mutants.out/<kind>.txt` via a temp file, so a resume of an interrupted resume keeps every earlier outcome), and a mutant under two outcomes is exit 1. `MUTANTS_PG_DURABILITY=off` (D-156: every `#[sqlx::test]` creates a database and migrates it, about 6× faster without durability): `DATABASE_URL` comes from the environment or the clone's `.env` (read as data by `bin/read-env`) and is split into `PGHOST`/`PGPORT`/`PGUSER`/`PGPASSWORD`/`PGDATABASE` for psql (psql reads neither `DATABASE_URL` nor a URL in `PGDATABASE`), never on an argv or in a log. `ALTER SYSTEM SET fsync, synchronous_commit, full_page_writes = off` plus `pg_reload_conf()` run before `--list`, and the same with `on` at EXIT/HUP/INT/TERM/QUIT/PIPE (SIGKILL and the OOM killer are the named residuals); a failed restore prints `WARNING durability was not restored` and turns exit 0 into 1. Any other value is refused. `tests/local-mutants.t.sh` adds about 35 cases and sub-assertions with a stub psql (the resume chain R0 → R1 interrupted → R2 included), each red first; docs/07 §2 Mutation
- v0.1.23 — `bin/build-lock.sh`: a stale lock is taken without a person (exchange BACKLOG 56: a harness crash left `/tmp/build.lock.d` behind at 22:49 UTC on 2026-10-15 and every box build waited until morning). A waiter takes a foreign lock only when ALL of these hold: `BUILD_LOCK_STALE` (default 900 s; 0 disables; at most 7 digits, else exit 2) is not 0, the pid is numeric without a leading zero, `/proc/1` exists and `/proc/<pid>` does not, `since=` has the owner file's own form and `date -u -d` parses it, now − since ≥ `BUILD_LOCK_STALE`, and the owner has a token. It renames the OWNER FILE aside (`owner.stale.<pid>`; only one waiter can win the rename, and the lock path is never vacated, so a third acquirer can never mkdir it), re-reads the token, removes the file and rmdirs the lock (a failing rmdir counts as held), prints `build-lock: took the stale lock of <who> (pid <pid>, since <since>): the holder is gone and the lock is older than <n>s` and retries mkdir at once; a different token is moved back. A live holder's lock is never taken, however old. The waiting hint names the rule and the by-hand removal. `tests/build-lock.t.sh`: the dead-old fixture becomes a taken case, the never-stolen controls use a live sleep holder, two waiters in lockstep serialise, an owner without `token=` is held, and 7 not-taken controls plus `BUILD_LOCK_STALE` validation are added, each red first; `tests/verify-lib.t.sh`'s held-lock fixture carries a current `since=`; docs/07 §4
