## 2. Process
1. **Lane = unit of work and review:** one worktree, one branch `<model>/<slug>`, one self-contained `TASK.md`, disjoint file ownership. Size lanes so one reviewer can review them in one pass. No chains of tiny tasks.
2. **Phase 0 before lanes:** the shared contract (types, schemas, config keys, stubs that fail loudly naming their lane) committed on the integration branch, compiled and tested. Each command/route a lane adds is registered in **its own file**, never a shared table. Codex reviews the Phase 0 migration before lanes start, not only at milestone end (`--fresh`, change-nothing brief, disposable checkout via `review-checkout`, then `review-verify-clean`); its blockers and majors are fixed in Phase 0 before the first dispatch. The Opus reviewer applies the SQL-semantics checklist of `agents/reviewer.md` (collation, check order, extractor vs in-transaction state, role privileges, rollback) to every migration and SQL text. (C2, founder 2026-10-03) The coordinator also writes the milestone spec's **Mutation functions** list here: the authorisation and state-transition functions the milestone affects, one regex per line, the functions file of `standards/bin/mutants` (C4, item 10).
3. **Instrument before dispatch:** `scripts/verify/mN.sh` with one section per lane, committed and **proven red per section** (failure named per lane). Chains `mN-1.sh`. Uses `standards/bin/verify-lib.sh` (`expect_out`: real exit code + its own diagnostic regex). A filter that matches no test exits 0 in `cargo test` and vitest (`cargo nextest` exits 4) — so every marker asserts a positive count or an explicit test path.
4. **Verify on committed bytes only.** The coordinator checks the lane branch (`git -C <worktree> status` clean, `git show`, explicit test paths, instrument section) and runs `standards/bin/check-scope <worktree> <base>` (exit 0 = every changed path is owned by the TASK's owned-paths block in §3, read by `standards/bin/owned-paths`; prose and bullets are never read as ownership) (C7, founder 2026-10-03). Self-reports carry no weight.
5. **Done is mechanized, not reviewer silence (founder, 2026-10-02; replaces the per-lane two-review rule).** The exit criterion of a lane is its instrument section, `check`, the controls and the merge-time mutation run. A review finding is admitted only when the coordinator turns it into a failing test or check on the committed bytes; a finding that cannot be expressed that way is an opinion and goes to the numbered backlog in NOTES.md, which founders prune each milestone. **Per lane: one review** (`reviewer`, Opus) for HIGH lanes, none beyond the instrument for LOW lanes; findings are candidates: reproduce on bytes, then fix with a regression control, or reject with evidence. Cross-vendor review happens **once per milestone** (item 7), not per lane, so a Codex usage limit never parks a lane. Measured in m1.1: per-lane Codex reviews found useful mediums but no blocker Opus had missed, and parked three lanes for about three hours each.
6. **One fix round, blockers only (founder, 2026-10-02).** One message with the review adjudicated (accept / accept-modified / reject + reason), a `## Revision` section in TASK.md, one more commit, then merge when the instrument is green and no blocker is open. A blocker is a defect with a reproduction that loses or corrupts results, points, identity or money, or breaks a gate. Findings are classified by impact, not by the label they arrive with: an untested race or a guard without a test is never "minor" — it is a major unless it meets the blocker definition. (C3, founder 2026-10-03) Majors (a Codex/reviewer "medium" at high confidence counts as major) wait for the milestone's one fix lane (item 7); minors and nits go to the backlog, except a few-line fix the lane can fold in. Items outside the lane's ownership go to the coordinator. Measured in m1.1: a fix round that absorbed every minor took 90 minutes; the review that produced it took 10. If a fix creates another serious defect, stop or narrow scope and ask the founder — never merge to satisfy a round limit. (C9, founder 2026-10-03)
6a. **Findings become rules.** At every milestone close the coordinator adds the recurring finding classes (m1.1: lock order, fail-open on error, unvalidated input, controls red for the wrong reason, env files read as code, placement-based risk) to docs/06's "Never" list, the TASK template's §4 hard rules and, where a check can express them, the instrument — so lanes stop producing them and the loop shrinks instead of repeating. Lanes stay small: one guard family per lane; a diff past a few hundred lines is split.
7. **Integrate, one bounded close (founder, 2026-10-02):** coordinator merges `--no-ff` into `integration/mN` from the primary checkout. Every coordinator merge edit gets its diff-only Opus review before the next lane merges or the PR opens (C1, founder 2026-10-03). After all lanes: **one milestone review** — Codex (`--fresh`, the combined brief with the milestone's decision list attacked as in `prompts/independent-review.md`; a fresh Opus session when Codex is usage-limited, D-056) — then **one fix lane** for its blockers and majors plus the majors parked by item 6, re-verified mechanically only (the sections of item 10's local-verification rule, controls, the mutation run of item 10, CI on the final head); a fix that touches a migration or a money path gets one targeted 10-minute Opus look at that file. Residual findings below blocker level go to the backlog. There is no fixed round limit to satisfy: if a fix creates another serious defect, stop or narrow scope and ask the founder — never merge to satisfy a round limit. (C9, founder 2026-10-03) Then **one PR `integration/mN` → `main`** (CI green; `risk-gate` lists the HIGH paths in its summary; the founder reads them with the report and merges). The `risk-gate` check runs the trusted `classify-risk` and `risk-gate` scripts of the pinned standards commit (`standards_ref` of the reusable `.github/workflows/risk-gate.yml`), never the copy in the PR's own `standards` submodule. Budget: a lane cycle of 45–75 minutes (build 30–45, review 10, fix 10, merge 5) and a close of 60–90 minutes; a lane that runs past its budget stops and reports, and the coordinator splits it.
7a. **Merge control is honour-system and the gate is informational (D-049 amended, founder 2026-10-02, solo developer).** GitHub forbids self-approval, so `risk-gate` never blocks: it classifies the PR and lists HIGH paths with reasons; the founder merges only with CI green and after reading that list and the milestone report. The coordinator never merges into `main`, never pushes, and never asks for a merge with CI red. Every change to this standards repo is itself a PR reviewed by `reviewer` and merged by the founder. Revisit when a second founder or collaborator joins.
7b. **WIP limit:** at most 3 lanes running at once across the workspace, at most 2 in one repo (game). `new-lane.sh` refuses beyond that; count running lanes before every dispatch.
8. **Decide, don't escalate.** Only decisions with lasting consequences go to founders, **max 4 per batch**, options weighed, recommendation first (`NOTES.md`). Everything else: decide, log in `DECISIONS.md`, build.
9. **State lives in files.** `DECISIONS.md` (append-only), `NOTES.md` (≤150 lines), lane reports in `docs/md-reports/` (≤120 lines). Chat is lost on compaction.
10. **Lane economy (m1.1, measured: a HIGH lane's minutes go to recompiles and verification, not to writing code).**
   - **Three cycles, not fifteen.** The lane writes every test its TASK names, runs them once against the unfixed code (the red batch), implements everything, runs them once (the green batch), then runs its controls once. More cycles only for a probe whose answer changes the design, named as such in the report.
   - **Verify once, at the right place.** A lane runs `standards/bin/check` and its own instrument section once at the end. Cross-section runs, the chained instrument and mutation testing are the coordinator's, at merge, in one pass. Local verification = current milestone sections + earlier sections whose paths the diff touches; the full chain runs in CI on the final head (C8, founder 2026-10-03; mechanising "which sections a diff touches" — a `# paths:` header per instrument section and a lister script — is a NOTES backlog item, as is whether the §1 Opus fallback covers C2's Phase 0 review while Codex is limited: the founder's F14 ruling, pending). Lane checks match the lane: front-end lanes run front-end checks only (`check --only web`), Rust lanes the relevant Rust checks (`check --only rust`), judged from the TASK's owned-paths block by `standards/bin/owned-paths --kind`; anything else, and integrated CI, runs everything (C6, founder 2026-10-03). A repo that separates the migration owner from the application role ships `scripts/db/app-role.sh`; the reusable Rust CI runs it after the migrations when present (v0.1.16).
   - **Controls are for database guards; Rust-level guards are proven by mutation at merge.** A trigger or constraint gets one `#[ignore]`d control that disables it and asserts the rule anyway (red for its own reason: expected count and its own assertion message). For a guard that lives in Rust (an auth check, a validation, a state-machine branch) the evidence is a killed mutant: at every lane merge the coordinator runs `standards/bin/mutants <disposable clone> <base> <crate> [<functions file>]`. Scope: changed lines PLUS the authorisation and state-transition functions the milestone affects, even if unchanged (the milestone spec lists them; one regex per line in the functions file). Unviable (compile-failing) mutants are not counted as caught: the report gives caught / missed / timeout / unviable separately. Fewest safe batches (one `--in-diff` batch, one `--re` batch), baseline skipped only after the wrapper's own green test run of the crate in the same clone; the harness's process controls stay on (build lock, disposable clone, `--timeout`, nextest). Every survivor gets a test that kills it or a written justification (C4, founder 2026-10-03). This is the "negative control executed red" of docs/06 for Rust-level guards, in both product repos; the batched red run replaces per-test "tests first".
   - **The TASK carries the contract.** §7 states every name, signature, error code, trigger name and expected output the lane must use; §1 lists only the files the lane edits plus those it must understand, one reason each. The coordinator read the code; the lane should not have to rediscover it.
   - **Reports are short.** Commit sha, files touched, one line per §5 command (pass or fail), deviations numbered with reasons, BLOCKED/UNPROVEN, proposed decisions. No verbatim pastes: the coordinator re-runs every check on the committed bytes and executes the controls itself; the self-report carries no weight (rule 4).
   - **Builds (C5, founder 2026-10-03).** One Rust build at a time across sessions: `standards/bin/build-lock.sh` holds the machine lock `${TMPDIR:-/tmp}/build.lock.d`; `check`, the instruments (`verify-lib.sh`), `dispatch-deepseek`'s judgement and `standards/bin/mutants` take it, and lanes and the coordinator run every other cargo command as `standards/bin/with-build-lock cargo …`. Cargo jobs are limited by `build.jobs` in the repo's `.cargo/config.toml` (`templates/cargo-config.toml`, a measured memory-safe value). One shared `CARGO_TARGET_DIR` per repo across worktrees, `<primary checkout>/target/shared`, with sccache as `RUSTC_WRAPPER` when installed. Cargo keys workspace crates by their path relative to the workspace root and judges freshness by mtime, so a shared target could run another worktree's compiled tests as this one's result: the lock library therefore records the worktree that last built in `target/shared/.standards-worktree` and, when a different worktree builds, first runs `cargo clean -p` for every workspace member (dependencies stay cached). Dispatch refuses below 15 GB free disk (`task-lint`). After a merge `standards/bin/prune-lane <worktree> <merged-into>` removes the lane's worktree, branch and review checkouts.

## 3. Founder review of a milestone PR (business logic, not line by line)
Read the milestone report, the specs it implements, the instrument output, and the adjudication tables; answer `standards/HUMAN_REVIEW_CHECKLIST.md`. Line-level scrutiny is delegated to Reviewer A/B, the combined and independent reviews, and machine checks. **Because the founder doesn't read lines and no second approver exists, the exchange additionally requires:** property + concurrency tests for every invariant in `standards/specs/correctness.md` §3, and the stdlib-only independent checker (`scripts/verify/ledger-check`) that recomputes balances from exported events without the engine's code.

## 4. Box and harness mechanics
- Lane dispatch uses `standards/prompts/dispatch-brief.md` verbatim. Worktrees are created by `standards/bin/new-lane.sh`, never by agents (tool-created worktrees can hang the session; the script is the one path that pins branch, TASK header, submodule and the lane's `.env` — seeded from `.env.example`, placeholders only — together, and it enforces the WIP limit).
- Pre-dispatch: `standards/bin/task-lint <worktree>` exits 0 before every dispatch, DeepSeek or `architect` (header, branch, base, the owned-paths block, sections, clean tree, submodule pointer synced, 15 GB free) (C7, founder 2026-10-03); a deliberately wrong test path exits non-zero there. After any `git merge --ff-only` (or other move of HEAD) inside a lane worktree, re-sync the pinned standards: `git -C <wt> -c protocol.file.allow=always -c submodule.standards.url=<primary>/standards submodule update -q --init` (task-lint refuses otherwise).
- Never `git stash`; never `pkill -f` (only PIDs you started); absolute paths and `git -C`.
- One full verify chain at a time per machine (`verify-lib.sh` takes a lock). Long runs go to the Bash tool's `run_in_background` with output redirected to a log in the scratchpad; the tool reports the exit when it finishes.
- One Rust build at a time per machine (`build.lock.d`, §2 item 10, C5, founder 2026-10-03); a holder that is gone leaves a stale lock that is removed by hand only after checking its pid (`rm <lock>/owner && rmdir <lock>`). Sessions never export their own `TMPDIR`: the verify and build locks live in `${TMPDIR:-/tmp}` and are machine-wide only while every session resolves it to `/tmp` (only the smoke and the tests point it at their own temp dir, to isolate themselves). Lock order is verify → build: `verify-lib.sh` takes the verify lock, then the build lock. `dispatch-deepseek`'s judgement takes the build lock first and its instrument then takes the verify lock, which refuses at once (exit 3) when another chain holds it — and such a chain may be the one waiting for the build lock — so a lane judgement that fails with "another verify chain is running" is a false red: re-judge it after that chain ends, and never run a verify chain beside a dispatch judgement.
- Migration (standards v0.1.15): a TASK whose §3 has only bullets is refused by `check-scope` and `task-lint` (exit 2, "TASK §3 has no owned-paths block"); give it the ```` ```owned ```` block of `templates/TASK.template.md` before the next check or dispatch.
- Command shape, for coordinator and lanes alike (auto mode prompts the founder for anything else): files change through Edit/Write only (no heredocs, `python3 -`, `sed -i`, `perl -pi`); one plain command per Bash call (`git -C`, `env -C <dir> <cmd>`), no `cd … &&` chains or loops; no `DATABASE_URL`, secrets or `PATH=` on a command line and no sourcing `.env` (the tools read it); never edit `.claude/settings*.json`. `.env` is data the tools read, never code: only `DATABASE_URL` is taken from it, literally, by `standards/bin/read-env` (`DATABASE_URL=$(sh standards/bin/read-env DATABASE_URL)`); nothing sources or evaluates it.
- Agents die (rate limits, kills). Lanes make one WIP commit as soon as tests pass locally (squashed at merge). Dead = listed running + output stale + no processes from the worktree → stop it, then a fresh agent with `standards/prompts/takeover.md`.
- Never read or tail a subagent's transcript; only its final report enters the coordinator context.
- Check `/usage` before spawning a burst; one 429 can kill every running agent.
- Codex plugin: jobs are tracked per repository/working directory — run `/codex:status` and `/codex:result` from the directory that launched them. `/codex:rescue` **can modify code**: per-lane Codex reviews run inside a disposable review checkout (`standards/bin/review-checkout`) with an explicit "change nothing" brief, followed by `review-verify-clean`. Model and effort come from `.codex/config.toml` (project must be trusted). **Do not enable the Codex review gate** (Stop-hook loop; drains usage).
- `git push` only by the coordinator, as its own command, after a founder's word.

## 5. Isolation
Workers run in a container or separate OS user: their worktree only, no Docker socket, no `~/.ssh`, no GitHub token, no production credentials, network limited to package registries and model endpoints; test Postgres reached over TCP. Reviewers: disposable clone, read-only tools, tamper check. DeepSeek variables exist only inside `dispatch-deepseek` (or the interactive `deepseek` shell function, which runs in a subshell). Permission settings are defence in depth, not the boundary.

## 6. DeepSeek usage
- Official integration: Claude Code pointed at `https://api.deepseek.com/anthropic` with a DeepSeek API key. Metered pay-per-token API, so scripted dispatch is ordinary API use (no coding-plan tool restrictions).
- Model names: `deepseek-flash` (legacy `deepseek-v4-flash` is retired and served by V4.1 Flash); `deepseek-v4-pro` exists but is not used by default. Unknown Claude model names sent to this endpoint are mapped by DeepSeek (opus → v4-pro, sonnet/haiku → flash), so **inside a DeepSeek session every "Claude" subagent is actually DeepSeek.** Reviews and Claude subagents run only from normal `claude` sessions.
- **Code leaves the machine to DeepSeek.** Allowed for game LOW lanes (player UI, docs); admin screens are HIGH (they resolve, void and reissue questions) and never go to DeepSeek (m1.1 O2). Never for the exchange (money core and sellable IP): its repo carries `.no-deepseek` and the script refuses. Never production data (domain rule 7). Founder override (D-073, 2026-10-02): a HIGH game lane may be implemented by DeepSeek from an Opus-written contract when `DISPATCH_ALLOW_HIGH=1`, with the Opus review mandatory; admin surfaces and the exchange never.
- Env vars follow DeepSeek's official Claude Code guide, including `CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432`. Deviation: effort defaults to `high` (guide: `max`); use `max` for hard LOW lanes.
- Lanes run with WebSearch/WebFetch disabled (DeepSeek's web search costs extra tokens and widens prompt-injection surface).
- The `claude-opus*` → `deepseek-v4-pro` mapping is billed at Pro price; lanes force subagents to `deepseek-flash`.
- Keep a small prepaid balance and a spend alert; a leaked key can only burn the balance.
- Verify at bootstrap: inside a `deepseek` session, `/status` shows the DeepSeek base URL; in a normal session it doesn't.
