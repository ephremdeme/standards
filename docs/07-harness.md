## 2. Process
1. **Lane = unit of work and review:** one worktree, one branch `model/slug`, one self-contained `TASK.md`, disjoint file ownership (the owned-paths block of TASK §3, read by `standards/bin/owned-paths`; prose is never ownership). One guard family per lane, sized for one review pass; a diff past a few hundred lines is split. No chains of tiny tasks.
2. **Phase 0 before lanes:** the shared contract (types, schemas, config keys, stubs that fail loudly naming their lane) committed on the integration branch, compiled and tested; each command or route a lane adds is registered in its own file, never a shared table. Where the repo's mutation gate uses a functions file, the spec lists the **Mutation functions** (the authorisation and state-transition functions the milestone affects, one regex per line). The Codex plan review runs before the first dispatch and its accepted blockers and majors are fixed in Phase 0. Every migration and SQL text is read against the SQL-semantics checklist of `agents/reviewer.md`.
3. **Instrument before dispatch:** `scripts/verify/mN.sh` with one section per lane, committed and **proven red per section** (failure named per lane), chaining `mN-1.sh`, built on `standards/bin/verify-lib.sh` (`expect_out`: real exit code plus its own diagnostic regex). A filter that matches no test exits 0 in `cargo test` and vitest (`cargo nextest` exits 4), so every marker asserts a positive count or an explicit test path. Trust-boundary guards (money, authorization, deletion, append-only, privilege) each get a negative control: one `#[ignore]`d test that disables the guard and asserts the rule anyway, red for its own message; a plain domain CHECK gets a positive test (D-085 item 5). Rust concurrency, locking and timing get a forced-interleaving test in the instrument (D-088 item 4).
4. **Verify on committed bytes only.** The integrator checks the lane branch (`git -C` status clean, `git show`, explicit test paths, the instrument section) and runs `standards/bin/check-scope` on the worktree and base (exit 0 = every changed path is owned). Self-reports carry no weight.
5. **A finding counts only as a failing test or check, and the fixer writes it** (D-084): every accepted blocker or major is fixed red-first (the failing test or control committed before the fix); a finding that cannot be a test becomes a founder decision or a known-issues entry with written reasoning (UNPROVEN), never a silent backlog item. Findings are classified by impact, not by their label: an untested race or a guard without a test is at least a major.
6. **Dispositions** (D-088 items 2 and 3): the integrator rejects or downgrades a finding only with executable counterevidence (a committed test reproducing the precondition, an exact privilege query, a constraint with its control); argument-only counterevidence goes to Fable (invariants, money, authorization, privacy, destructive operations) or the founder (business or irreversible contract decisions). The review report stays unchanged, the disposition is written beside it, and an implementer never alone judges a finding against its own code. Known issues in a Codex brief are DECISIONS/BACKLOG IDs with the accepted failure path, re-raisable only on the D-088 item 3 grounds.
7. **Fix loops** (D-088 item 1). A blocker is a defect with a reproduction that loses or corrupts results, points, identity or money, or breaks a gate. Per lane, one in-lane fix round for blockers only and at most two review rounds. Per milestone, every accepted blocker or major affecting correctness, authorization, privacy, data integrity, destructive behaviour or the acceptance contract blocks close and is fixed red-first in one consolidated fix lane; a test-gap major goes to the mutation path; minor hardening goes to BACKLOG.md. Two review rounds are a re-planning trigger, never permission to close over a consequential defect; if a fix creates another serious defect, stop or narrow scope and ask the founder.
8. **Integrate and close:** the integrator merges `--no-ff` into `integration/mN` from the primary checkout; after the last lane, the Codex integrated review, the fix lane, the fix-delta re-read, then one PR `integration/mN` → `main`. The gates (D-085, D-088):
   - **Mutation:** `cargo mutants --in-diff` against the milestone base, once at close, in CI (not on the 8 GB machine); `open survivors: 0` tied to HEAD; unviable and timeout are not caught; every survivor gets a killing test or written reasoning. A full sweep of the dangerous files runs in CI before any deploy milestone and at most monthly otherwise; a lane that edits an existing assertion declares it, and the integrator mutates the files those tests cover (D-088 item 5).
   - **CI:** pull requests run the chain in parallel section groups (D-087); a milestone PR also needs the full sequential chain green on its exact head (`gh workflow run nightly --ref integration/mN`), which is the `full chain:` evidence (D-088 item 8).
   - **Trust boundary:** the close report lists the trust-boundary files changed; the risk-gate workflow is retired and `classify-risk` stays a pre-dispatch aid (D-085 item 3).
   - **Merge:** non-milestone PRs on green CI with `--match-head-commit`; milestone PRs through `merge-pr --milestone` (D-088 item 7, D-089).
9. **WIP limit:** at most 3 lanes running at once across the workspace, at most 2 in one repo. `new-lane.sh` refuses beyond that.
10. **Decide, don't escalate.** Only decisions with lasting consequences go to founders, **max 4 per batch**, options weighed, recommendation first (`NOTES.md`). Everything else: decide, log in `DECISIONS.md`, build.
11. **State lives in files** (D-085 item 6): `DECISIONS.md` (append-only, read by grep), `NOTES.md` "Where we are" at most ~60 lines, `BACKLOG.md`, lane and close reports in `docs/md-reports/` (≤120 lines). At every close the recurring finding classes become rules: docs/06 "Never", the TASK template's §4, and the instrument where a check can express them.
12. **Lane economy:**
   - **Three cycles, not fifteen.** Write every test the TASK names, run them once against the unfixed code (red batch), implement everything, run them once (green batch), run the controls once. More cycles only for a probe whose answer changes the design, named in the report.
   - **Verify once, at the right place.** A lane runs `standards/bin/check --only kind` (kind from `standards/bin/owned-paths --kind`) and its own instrument section once at the end. Cross-section runs, the chain and mutation are the integrator's and CI's. A repo that separates the migration owner from the application role ships `scripts/db/app-role.sh`; the reusable Rust CI runs it after the migrations.
   - **The TASK carries the contract.** §7 states every name, signature, error code, trigger name and expected output; §1 lists only the files the lane edits or must understand, one reason each.
   - **Reports are short.** Commit sha, files touched, one line per §5 command, deviations numbered with reasons, BLOCKED/UNPROVEN, proposed decisions. No verbatim pastes.
   - **Builds (C5).** One Rust build at a time across sessions: `standards/bin/build-lock.sh` holds the machine lock `${TMPDIR:-/tmp}/build.lock.d`; `check`, the instruments, `dispatch-deepseek`'s product judgement and `standards/bin/mutants` take it, and every other cargo command runs as `standards/bin/with-build-lock cargo …`. `build.jobs` in `.cargo/config.toml` (`templates/cargo-config.toml`) caps memory. One shared `CARGO_TARGET_DIR` per repo, `target/shared` of the primary checkout, with sccache when installed; the lock library records the last building worktree in `target/shared/.standards-worktree` and runs `cargo clean -p` for the workspace members when another worktree builds, so a stale binary never runs as this worktree's result. Dispatch refuses below 15 GB free disk (`task-lint`). After a merge `standards/bin/prune-lane` removes the lane's worktree, branch and review checkouts.

## 3. Founder review of a milestone PR (business logic, not line by line)
Read the close report (with its trust-boundary file list and the finding dispositions), the specs it implements and the instrument output; answer `standards/HUMAN_REVIEW_CHECKLIST.md`; apply `founder-approved` after the newest push of the head branch. Line-level scrutiny is delegated to the reviews and the machine checks. **Because the founder doesn't read lines, the exchange additionally requires:** property and concurrency tests for every invariant in `standards/specs/correctness.md` §3, and the stdlib-only checker `scripts/verify/ledger-check` that recomputes balances from exported events without the engine's code.

## 4. Box and harness mechanics
- Lane dispatch uses `standards/prompts/dispatch-brief.md` verbatim. Worktrees come from `standards/bin/new-lane.sh`, never from agents (it pins branch, TASK header, submodule and the lane's `.env`, placeholders only, and enforces the WIP limit).
- Pre-dispatch: `standards/bin/task-lint` on the worktree exits 0 before every dispatch, DeepSeek or `architect` (header, branch, base, the owned-paths block, sections, clean tree, submodule pointer, 15 GB free). After any move of HEAD inside a lane worktree, re-sync the pinned standards with the `submodule update` command task-lint prints.
- **DeepSeek dispatch** (`dispatch-deepseek`): refused for repos marked `.no-deepseek` (judged on the primary checkout's committed tree), for any admin surface, and for `Risk: HIGH` without `DISPATCH_ALLOW_HIGH=1` (game D-073); a dispatcher copy inside the lane worktree is refused. A product lane is judged after the run on bytes: new commits, a clean tree, nothing changed under `scripts/verify/`, `standards` or `.gitmodules`, then `check --only kind` and the TASK §5 instrument section taken from the pre-run commit. A **standards docs lane** (the standards repo, recognised by its root commit): every owned path and every changed path (both sides of a rename) is a literal path in `docs/` except `docs/05*`, the prose templates `templates/*.md` (one segment), `CHANGELOG.md` or `README.md`, never an agent-instruction file (`CLAUDE.md`, `CLAUDE.local.md`, `AGENTS*.md`) or a dot segment, and every committed mode is 100644; TASK §5 names its judges as `sh tests/name.t.sh`; after the run each of them and the markdown judge `tests/docs.t.sh --judge` (relative links resolve, no template placeholders) on every `docs/**/*.md` and `README.md` run from a tree built from the pre-run commit. The integrator still reads the diff.
- **Push and merge** (D-086, D-089): agents push only through `standards/bin/push-branch` (one `integration/*` or `opus|fable|ds/*` branch, fast-forward, or one annotated `vN.N.N` standards tag; never forced, never `main`; the origin URL and root commit checked per repository) and merge only through `standards/bin/merge-pr` (an open same-repository PR with that exact head, the pinned check runs green, then `gh pr merge --merge --match-head-commit`). `founder-approved`, applied after the head branch's newest push, is required for every `integration/*` PR and for PRs changing `.github/**`, `.claude/**` or CODEOWNERS; an `integration/mN` PR runs with `--milestone mN`, which reads the nightly chain, `codex-last-read:` and `human-gate-accepted` (or `--residual D-NNN`) from GitHub at the SHA. Both refuse with exit 2 and fail closed. Standards has no PR CI: its `--smoke-log` is integrator-attested. Raw `git push`, `gh pr merge` and label writes are denied in the founder's settings.
- One full verify chain at a time per machine (`verify-lib.sh` takes a lock); long runs go to the Bash tool's `run_in_background` with output in the scratchpad. One Rust build at a time (§2 item 12); a stale lock is removed by hand only after checking its pid (`rm lock/owner && rmdir lock`). Sessions never export their own `TMPDIR`: the locks live in `${TMPDIR:-/tmp}` and are machine-wide only while every session resolves it to `/tmp`. Lock order is verify → build. A product lane judgement of `dispatch-deepseek` holds the build lock and then needs the verify lock, so its "another verify chain is running" is a false red: re-judge after that chain ends, and never run a chain beside a dispatch judgement.
- Command shape, for integrator and lanes alike (auto mode prompts the founder for anything else): files change through Edit/Write only (no heredocs, `python3 -`, `sed -i`, `perl -pi`); one plain command per Bash call (`git -C`, `env -C`), no `cd … &&` chains or loops; no `DATABASE_URL`, secrets or `PATH=` on a command line and no sourcing `.env` (`standards/bin/read-env` reads `DATABASE_URL` from it as data); never edit `.claude/settings*.json`. Never `git stash`; never `pkill -f` (only PIDs you started).
- Agents die (rate limits, kills). Lanes make one WIP commit as soon as tests pass locally (squashed at merge). Dead = listed running + output stale + no processes from the worktree → stop it, then a fresh agent with `standards/prompts/takeover.md`. Never read or tail a subagent's transcript; only its final report enters the integrator's context. Check `/usage` before spawning a burst; one 429 can kill every running agent.
- Codex plugin: jobs are tracked per working directory — `/codex:status` and `/codex:result` from the directory that launched them. `/codex:rescue` **can modify code**, hence the review checkout and `review-verify-clean`. Model and effort come from `.codex/config.toml` (project must be trusted). **Do not enable the Codex review gate** (Stop-hook loop; drains usage).

## 5. Isolation
Workers run in a container or separate OS user: their worktree only, no Docker socket, no `~/.ssh`, no GitHub token, no production credentials, network limited to package registries and model endpoints; test Postgres reached over TCP. Reviewers: disposable clone, read-only tools, tamper check. DeepSeek variables exist only inside `dispatch-deepseek` (or the interactive `deepseek` shell function, which runs in a subshell). Permission settings are defence in depth, not the boundary.

## 6. DeepSeek usage
- Official integration: Claude Code pointed at `https://api.deepseek.com/anthropic` with a DeepSeek API key. Metered pay-per-token API, so scripted dispatch is ordinary API use (no coding-plan tool restrictions).
- Model names: `deepseek-flash` (legacy `deepseek-v4-flash` is retired and served by V4.1 Flash); `deepseek-v4-pro` exists but is not used by default. Unknown Claude model names sent to this endpoint are mapped by DeepSeek (opus → v4-pro, sonnet/haiku → flash), so **inside a DeepSeek session every "Claude" subagent is actually DeepSeek.** Reviews and Claude subagents run only from normal `claude` sessions.
- **Code leaves the machine to DeepSeek.** Never for the exchange (money core and sellable IP): its repo carries `.no-deepseek` and the script refuses. Never admin screens (they resolve, void and reissue questions; m1.1 O2). Never production data (domain rule 7).
- Env vars follow DeepSeek's official Claude Code guide, including `CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432`. Effort defaults to `max`, as in the guide (founder 2026-10-06), in both the dispatcher and `templates/deepseek.sh`; `high` stays available (`dispatch-deepseek` with `high` as its second argument, `DS_EFFORT=high deepseek`). Shell profiles source the template instead of copying it, so the interactive launcher cannot drift from the dispatcher.
- Lanes run with WebSearch/WebFetch disabled (DeepSeek's web search costs extra tokens and widens prompt-injection surface). The `claude-opus*` → `deepseek-v4-pro` mapping is billed at Pro price; lanes force subagents to `deepseek-flash`.
- Keep a small prepaid balance and a spend alert; a leaked key can only burn the balance. Verify at bootstrap: inside a `deepseek` session, `/status` shows the DeepSeek base URL; in a normal session it doesn't.
