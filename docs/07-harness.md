## 2. Process
1. **Lane = unit of work and review:** one worktree, one branch `model/slug`, one self-contained `TASK.md`, disjoint file ownership (the owned-paths block of TASK §3, read by `standards/bin/owned-paths`; prose is never ownership). One guard family per lane, sized for one review pass; a diff past a few hundred lines is split. No chains of tiny tasks.
2. **Phase 0 before lanes:** the shared contract (types, schemas, config keys, stubs that fail loudly naming their lane) committed on the integration branch, compiled and tested; each command or route a lane adds is registered in its own file, never a shared table. Where the repo's mutation gate uses a functions file, the spec lists the **Mutation functions** (the authorisation and state-transition functions the milestone affects, one regex per line). The Codex plan review runs before the first dispatch and its accepted blockers and majors are fixed in Phase 0; before that review the integrator commits the spec's skeleton (instrument, stubs, contract) on the integration branch and proves every instrument section red on committed bytes, and a finding that only the red report can raise after the plan re-read becomes a DECISIONS line or a known issue, not a further plan read (R2). Every migration and SQL text is read against the SQL-semantics checklist of `agents/reviewer.md`.
3. **Instrument before dispatch:** `scripts/verify/mN.sh` with one section per lane, committed and **proven red per section** (failure named per lane), chaining `mN-1.sh`, built on `standards/bin/verify-lib.sh` (`expect_out`: real exit code plus its own diagnostic regex). A filter that matches no test exits 0 in `cargo test` and vitest (`cargo nextest` exits 4), so every marker asserts a positive count or an explicit test path. Trust-boundary guards (money, authorization, deletion, append-only, privilege) each get a negative control: one `#[ignore]`d test that disables the guard and asserts the rule anyway, red for its own message; a plain domain CHECK gets a positive test (D-085 item 5). Rust concurrency, locking and timing get a forced-interleaving test in the instrument (D-088 item 4).
4. **Verify on committed bytes only.** The integrator checks the lane branch (`git -C` status clean, `git show`, explicit test paths, the instrument section) and runs `standards/bin/check-scope` on the worktree and base (exit 0 = every changed path is owned). Self-reports carry no weight.
5. **A finding counts only as a failing test or check, and the fixer writes it** (D-084): every accepted blocker or major is fixed red-first (the failing test or control committed before the fix); a finding that cannot be a test becomes a founder decision or a known-issues entry with written reasoning (UNPROVEN), never a silent backlog item. Findings are classified by impact, not by their label: an untested race or a guard without a test is at least a major.
6. **Dispositions** (D-088 items 2 and 3): the integrator rejects or downgrades a finding only with executable counterevidence (a committed test reproducing the precondition, an exact privilege query, a constraint with its control); argument-only counterevidence goes to Fable (invariants, money, authorization, privacy, destructive operations) or the founder (business or irreversible contract decisions). The review report stays unchanged, the disposition is written beside it, and an implementer never alone judges a finding against its own code. Known issues in a Codex brief are DECISIONS/BACKLOG IDs with the accepted failure path, re-raisable only on the D-088 item 3 grounds.
7. **Fix loops** (D-088 item 1). A blocker is a defect with a reproduction that loses or corrupts results, points, identity or money, or breaks a gate. Per lane, one in-lane fix round for blockers only and at most two review rounds. (R3) An accepted major from the lane review does not stop the lane: as the integrator's disposition table directs (`blocker → in-lane, one round`; `major → fix lane`; `minor → BACKLOG`), the lane's implementer commits, in its final commit, one red `#[test] fn fix_<id>()` in the lane's own test binary whose panic text quotes the finding; the instrument's positive run of that binary stays red until the one consolidated fix lane turns it green. The integrator writes no code and the instrument file keeps its single owner (Phase 0): no lane edits `scripts/verify/mN.sh`. More than twelve open majors at close is the re-planning trigger of this item, never a reason for parallel fix lanes; there is never a third round. Per milestone, every accepted blocker or major affecting correctness, authorization, privacy, data integrity, destructive behaviour or the acceptance contract blocks close and is fixed red-first in one consolidated fix lane; a test-gap major goes to the mutation path; minor hardening goes to BACKLOG.md. Two review rounds are a re-planning trigger, never permission to close over a consequential defect; if a fix creates another serious defect, stop or narrow scope and ask the founder.
8. **Integrate and close:** the integrator merges `--no-ff` into `integration/mN` from the primary checkout; after the last lane, the Codex integrated review, the fix lane, the fix-delta re-read, then one PR `integration/mN` → `main`. The gates (D-085, D-088):
   - **Mutation (D-110):** `cargo mutants --in-diff` against the milestone base, once at close, on the dev machine under a memory cap: `standards/bin/local-mutants <clone> <base> <crate> [--tests <name>,…]` in a disposable clone runs every cargo mutants call inside `systemd-run --user --scope -p MemoryMax=3G -p MemorySwapMax=0` (`MUTANTS_MEMORY_MAX` overrides; without systemd-run or the scope nothing runs), `--jobs 1`, the baseline uncapped and each mutant's tests capped at twice the baseline's test time, at least 60 s (`--minimum-test-timeout 60 --timeout-multiplier 2`, exchange D-155: a fixed `--timeout 60` also capped the baseline), nextest, the replay proptest excluded, sccache on (`MUTANTS_NO_SCCACHE=1` is the explicit opt-out), `--resume <out-dir>` resumes an interrupted run in its own outcome directory with `cargo mutants --iterate` (refused unless the clone, base, HEAD, diff and listing are unchanged; caught and unviable are counted as the union of the earlier and the new outcome files, so tested still equals the listing), `MUTANTS_PG_DURABILITY=off` turns the dev database's fsync, synchronous_commit and full_page_writes off for the run and back on at every exit (a failed restore is a loud WARNING and exit 1; `DATABASE_URL` from the environment or the clone's `.env`, never on an argv), and prints one `run:` line whose tested count must equal `cargo mutants --list`. The Actions `mutants` workflow stays in the tree, dormant. `open survivors: 0` tied to HEAD; unviable and timeout are not caught; every survivor gets a killing test or written reasoning. (R5) The economy lever is the `--tests` list and the memory cap, never the file scope: the run is in-diff over every changed `src` file of the crate, and `--tests` names the milestone's test binaries plus every earlier test binary changed since the base; the mutation ledger carries that list on a `tests:` line and the instrument's ledger reader refuses an omission. Mutation has found no product bug in either repo so far; its value is the test gap it names. A full sweep of the dangerous files runs before any deploy milestone and at most monthly otherwise; a lane that edits an existing assertion declares it, and the integrator mutates the files those tests cover (D-088 item 5). **Rehearse before the close (E4 lost about 10 hours to three mutation-tooling defects found only at the close):** right after the Phase 0 merge the integrator runs one short `local-mutants` (or `runner mutants`) probe on the merged head with the Phase 0 binaries, records its rate and baseline time in a DECISIONS line, and plans the close run from it.
   - **CI = the local evidence log (D-109):** GitHub-hosted Actions are dropped; their workflows stay in the tree, dormant, and a self-hosted runner can revive the check-runs path. `standards/bin/local-gate <repo> <mN> <log>` runs `check` (under the build lock) and the full sequential chain `scripts/verify/<mN>.sh` on a clean tree into a fresh log that starts with `free -m` and always ends, red or green, with `gate-head: <sha>`, `gate-tree: clean` (tracked files and HEAD re-read at the end, else `gate-tree: dirty (<path>)`) and exactly one `gate-verdict: green <mN>` or `gate-verdict: red — <reason>`, which the gate decides from its exit codes as well as the log, because chained instruments print green `verify:` lines of their own before the outer run can still fail. `<mN>` must be the newest `scripts/verify/<id>.sh` of the repo (ids `[a-z][a-z0-9_]*`, ordered by their numbers: e2 > e1 > m0, m2_2 > m2_1), so every PR is backed by the current chain; `LOCAL_GATE_INSTRUMENT_OVERRIDE=1` runs an older one and the log says so (`gate-instrument: <id> (override)`). That log is "CI green" for any exchange or game PR and, for a milestone PR, the `full chain:` evidence on the exact head. The evidence is integrator-attested, bound to the SHA by `gate-head`, and checked by Codex's integrated review and the human gate.
   - **Trust boundary:** the close report lists the trust-boundary files changed; the risk-gate workflow is retired and `classify-risk` stays a pre-dispatch aid (D-085 item 3).
   - **Merge:** every exchange or game PR through `merge-pr --local-log <log>` (standards: `--smoke-log`), milestone PRs with `--milestone mN` as well (D-088 item 7, D-089, D-109).
9. **WIP limit:** at most 5 lanes running at once across the workspace, at most 2 in one repo. `new-lane.sh` refuses beyond that.
10. **Decide, don't escalate.** Only decisions with lasting consequences go to founders, **max 4 per batch**, options weighed, recommendation first (`NOTES.md`). Everything else: decide, log in `DECISIONS.md`, build.
11. **State lives in files** (D-085 item 6): `DECISIONS.md` (append-only, read by grep), `NOTES.md` "Where we are" at most ~60 lines, `BACKLOG.md`, lane and close reports in `docs/md-reports/` (≤120 lines). (R4) Every close report carries one line `Tokens: integrator avg_ctx=<k>k calls_per_merge=<n>; lanes avg_ctx=<k>k requests=<n>; codex reads=<n>`, produced with `python3 -I /srv/work/hub/outputs/reviews/usage_audit2.py <milestone start YYYY-MM-DD> '/home/ephrem/.claude/projects/-srv-work-<repo>/**/*.jsonl' '/home/ephrem/.claude/projects/-srv-work/**/*.jsonl'`; the instrument checks the format, and the human gate reads the numbers against the targets (integrator ≤ 150k average context, D-083; ≤ 15 calls per merge cycle; nothing had been measured since the integrator model was adopted). At every close the recurring finding classes become rules: docs/06 "Never", the TASK template's §4, and the instrument where a check can express them.
12. **Lane economy:**
   - **Three cycles, not fifteen.** Write every test the TASK names, run them once against the unfixed code (red batch), implement everything, run them once (green batch), run the controls once. More cycles only for a probe whose answer changes the design, named in the report.
   - **Verify once, at the right place.** A lane runs `standards/bin/check --only kind` (kind from `standards/bin/owned-paths --kind`) and its own instrument section once at the end. Cross-section runs, the chain and mutation are the integrator's (`local-gate`, `local-mutants`; D-109, D-110). A repo that separates the migration owner from the application role ships `scripts/db/app-role.sh`; the reusable Rust CI runs it after the migrations.
   - **The TASK carries the contract.** §7 states every name, signature, error code, trigger name and expected output; §1 lists only the files the lane edits or must understand, one reason each.
   - **Reports are short.** Commit sha, files touched, one line per §5 command, deviations numbered with reasons, BLOCKED/UNPROVEN, proposed decisions. No verbatim pastes.
   - **Builds (C5).** One Rust build at a time across sessions: `standards/bin/build-lock.sh` holds the machine lock `${TMPDIR:-/tmp}/build.lock.d`; `check` (under `local-gate` too), the instruments, `dispatch-deepseek`'s product judgement, `standards/bin/mutants` and `standards/bin/local-mutants` take it, and every other cargo command runs as `standards/bin/with-build-lock cargo …`; a stale build lock is taken automatically under the `BUILD_LOCK_STALE` rule of §4, any other held lock is waited for. `build.jobs` in `.cargo/config.toml` (`templates/cargo-config.toml`) caps memory. One shared `CARGO_TARGET_DIR` per repo, `target/shared` of the primary checkout, with sccache when installed (on PATH or in `$HOME/.cargo/bin`, named in a `build-lock: sccache <path>` line); the lock library records the last building worktree in `target/shared/.standards-worktree` and runs `cargo clean -p` for the workspace members when another worktree builds, so a stale binary never runs as this worktree's result; the cargo workspace may be one tracked subdirectory instead of the top (a `Cargo.toml` with a `[workspace]` header line, indented or with a trailing comment, at most 3 levels deep; several refuse), and the shared target, the switch clean and the stamp follow it. A Go module (`go.mod` at the repo top) makes `check` run `make gen` with the committed-output check (gen must change nothing in the working tree), `make lint` and `make test`, outside the build lock (exchange D-158); gitignored generated files are outside the committed-output check, and the Makefile's `gen`, `lint` and `test` targets must be `.PHONY` (a same-named file or directory makes make skip the recipe); a Go lane runs `check --only go`. Dispatch refuses below 15 GB free disk (`task-lint`). After a merge `standards/bin/prune-lane` removes the lane's worktree, branch and review checkouts.

## 3. Founder review of a milestone PR (business logic, not line by line)
Read the close report (with its trust-boundary file list and the finding dispositions), the specs it implements and the instrument output; answer `standards/HUMAN_REVIEW_CHECKLIST.md`; apply `founder-approved` after the newest push of the head branch. Line-level scrutiny is delegated to the reviews and the machine checks. **Because the founder doesn't read lines, the exchange additionally requires:** property and concurrency tests for every invariant in `standards/specs/correctness.md` §3, and the stdlib-only checker `scripts/verify/ledger-check` that recomputes balances from exported events without the engine's code.

## 4. Box and harness mechanics
- Lane dispatch uses `standards/prompts/dispatch-brief.md` verbatim. Worktrees come from `standards/bin/new-lane.sh`, never from agents (it pins branch, TASK header, submodule and the lane's `.env`, placeholders only, and enforces the WIP limit).
- Pre-dispatch: `standards/bin/task-lint` on the worktree exits 0 before every dispatch, DeepSeek or `architect` (header, branch, base, the owned-paths block, sections, the §2 `Complexity:` and `Tags:` lines (R6), clean tree, submodule pointer, 15 GB free). After any move of HEAD inside a lane worktree, re-sync the pinned standards with the `submodule update` command task-lint prints.
- **DeepSeek dispatch** (`dispatch-deepseek`): refused for repos marked `.no-deepseek` (judged on the primary checkout's committed tree), for any admin surface, and for `Risk: HIGH` without `DISPATCH_ALLOW_HIGH=1` (game D-073); a dispatcher copy inside the lane worktree is refused. **Lane-scoped override (exchange D-161):** a committed `.deepseek-lanes` (lines `<branch> D-<number>`, one space; empty and `#` lines ignored) lifts `.no-deepseek` for exactly the branches it names. It is read only from the TASK's `Base:` commit, never from the worktree or the lane's commits, and only when a branch head that `git ls-remote origin` reports contains that Base (a lane cannot push, so it cannot move Base to a listing of its own; a hand-made `refs/remotes/` ref proves nothing); replace objects are off, and a `refs/replace/` ref, an `info/grafts` file or a `shallow` file in the shared `.git` refuses the override; because the listing is read at the lane's Base, revoking a lane means removing its line from `.deepseek-lanes` AND re-cutting (or pruning) its worktree; the TASK's `Branch:` must equal a listed branch exactly (no prefix or regex); a malformed line or a branch listed twice refuses every lane of the repo; the dispatcher prints the override with the decision it cites; every other refusal still applies; and a lane that changes `.deepseek-lanes` or `.no-deepseek` fails as "lane changed its own judge". A product lane is judged after the run on bytes: new commits, a clean tree, nothing changed under `scripts/verify/`, `standards`, `.gitmodules`, `.deepseek-lanes` or `.no-deepseek`, then `check --only kind` and the TASK §5 instrument section (`scripts/verify/<id>.sh --section <name>`, `<id>` in local-gate's grammar `[a-z][a-z0-9_]*`: `gp`, `e4`, `m2_2`) taken from the pre-run commit. A **standards docs lane** (the standards repo, recognised by its root commit): every owned path and every changed path (both sides of a rename) is a literal path in `docs/` except `docs/05*`, the prose templates `templates/*.md` (one segment), `CHANGELOG.md` or `README.md`, never an agent-instruction file (`CLAUDE.md`, `CLAUDE.local.md`, `AGENTS*.md`) or a dot segment, and every committed mode is 100644; TASK §5 names its judges as `sh tests/name.t.sh`; after the run each of them and the markdown judge `tests/docs.t.sh --judge` (relative links resolve, no template placeholders) on every `docs/**/*.md` and `README.md` run from a tree built from the pre-run commit. The integrator still reads the diff.
- **Push and merge** (D-086, D-089, D-109): agents push only through `standards/bin/push-branch` (one `integration/*` or `opus|fable|ds/*` branch, fast-forward, or one annotated `vN.N.N` standards tag; never forced, never `main`; the origin URL and root commit checked per repository) and merge only through `standards/bin/merge-pr` (an open same-repository PR with that exact head; for exchange and game the local gate log through `--local-log <log>`, which replaces the check runs and the commit status: at least one `check: OK` line, exactly one verdict line, `gate-verdict: green <id>`, with a `verify:<id> — N ok, 0 failed` line (N ≥ 1) for that id, no `check: FAILED`, `[FAIL]` or failed `verify:` line, every `gate-head:` line equal to the head and every `gate-tree:` line `clean`; without `--local-log` the pinned check runs green; then `gh pr merge --merge --match-head-commit`). The integrator produces the log with `local-gate` on the exact head, in the background like any chain. `founder-approved`, applied after the head branch's newest push, is required for every `integration/*` PR and for PRs changing `.github/**`, `.claude/**` or CODEOWNERS; an `integration/mN` PR runs with `--milestone mN`, which reads `codex-last-read:` and `human-gate-accepted` (or `--residual D-NNN`) from GitHub at the SHA and takes the full chain from the log, whose verdict must be `gate-verdict: green mN` (from the nightly run without `--local-log`). Both refuse with exit 2 and fail closed. Standards has no PR CI: its `--smoke-log` is integrator-attested, and so is `--local-log`. Raw `git push`, `gh pr merge` and label writes are denied in the founder's settings.
- **Integrator wrappers** (one call per check, so logs never enter an agent's context): `standards/bin/lane-verify <worktree> <base> [--section <id> <name>]` accepts a lane (tree, branch, task-lint, check-scope, risk, the section's verdict lines only); `standards/bin/gate-summary <log> [--id <mN>]` reads a local-gate log and prints its verdict exactly as `merge-pr --local-log` would judge it; `standards/bin/close-check <repo-dir> <mN> <pr> [--log <path>]` runs the milestone-close rows (head, pr, labels, codex-last-read = head, mutation ledger tied to HEAD per crate, report lines, gate) reading every report as committed at HEAD. Each is read-only, prints one line per rule and a verdict, exits non-zero on any failure, and has its judge `tests/<name>.t.sh` with a red control per rule.
- One full verify chain at a time per machine (`verify-lib.sh` takes a lock with an owner file); a held verify lock is waited for like the build lock, up to `VERIFY_LOCK_WAIT` seconds (default 1800, polled every 10 s; 0 refuses at once), then refused with exit 3 naming the holder, so a lane's section run queues behind an integrator's local gate instead of killing it. A run nested inside the holder (an instrument that runs another instrument after sourcing verify-lib) is refused at once: chain instruments from a script that does not source it. Long runs go to the Bash tool's `run_in_background` with output in the scratchpad. One Rust build at a time (§2 item 12); Go takes no lock: `check` on a Go module (`go.mod`) runs `make gen` with the committed-output check, `make lint` and `make test` outside the build lock (exchange D-158; gitignored generated files are outside the committed-output check; the three targets must be `.PHONY`), and `--only go` runs that block alone; a stale build lock (holder pid not running on this box and the lock older than `BUILD_LOCK_STALE` seconds, default 900; 0 disables) is taken automatically by the next waiter with a `build-lock: took the stale lock of …` line; a younger one, or any lock whose holder may be alive, is waited for and refused as before, and is removed by hand only after checking its pid (`rm lock/owner && rmdir lock`). The verify lock is never removed automatically. Sessions never export their own `TMPDIR`: the locks live in `${TMPDIR:-/tmp}` and are machine-wide only while every session resolves it to `/tmp`. Lock order is verify → build. A product lane judgement of `dispatch-deepseek` holds the build lock and then needs the verify lock; waiting there would deadlock with a chain waiting for that build lock, so a run that already holds the build lock is refused at once ("refused — the verify lock is held … after waiting 0s"), a false red: re-judge after that chain ends, and never run a chain beside a dispatch judgement.
- Command shape, for integrator and lanes alike (auto mode prompts the founder for anything else): files change through Edit/Write only (no heredocs, `python3 -`, `sed -i`, `perl -pi`); one plain command per Bash call (`git -C`, `env -C`), no `cd … &&` chains or loops; no `DATABASE_URL`, secrets or `PATH=` on a command line and no sourcing `.env` (`standards/bin/read-env` reads `DATABASE_URL` from it as data); never edit `.claude/settings*.json`. Never `git stash`; never `pkill -f` (only PIDs you started).
- Agents die (rate limits, kills). Lanes make one WIP commit as soon as tests pass locally (squashed at merge). Dead = listed running + output stale + no processes from the worktree → stop it, then a fresh agent with `standards/prompts/takeover.md`. Never read or tail a subagent's transcript; only its final report enters the integrator's context. Check `/usage` before spawning a burst; one 429 can kill every running agent.
- Codex plugin: jobs are tracked per working directory — `/codex:status` and `/codex:result` from the directory that launched them. `/codex:rescue` **can modify code**, hence the review checkout and `review-verify-clean`. Model and effort come from `.codex/config.toml` (project must be trusted). That file is per repo and pinned on the milestone's spec branch; from an agent session outside the repo directory, `--model` and `--effort` are passed explicitly (§1, R2). **Do not enable the Codex review gate** (Stop-hook loop; drains usage).

## 5. Isolation
Workers run in a container or separate OS user: their worktree only, no Docker socket, no `~/.ssh`, no GitHub token, no production credentials, network limited to package registries and model endpoints; test Postgres reached over TCP. Reviewers: disposable clone, read-only tools, tamper check. DeepSeek variables exist only inside `dispatch-deepseek` (or the interactive `deepseek` shell function, which runs in a subshell). Permission settings are defence in depth, not the boundary.

## 6. DeepSeek usage
- Official integration: Claude Code pointed at `https://api.deepseek.com/anthropic` with a DeepSeek API key. Metered pay-per-token API, so scripted dispatch is ordinary API use (no coding-plan tool restrictions).
- Model names: `deepseek-flash` (legacy `deepseek-v4-flash` is retired and served by V4.1 Flash); `deepseek-v4-pro` exists but is not used by default. Unknown Claude model names sent to this endpoint are mapped by DeepSeek (opus → v4-pro, sonnet/haiku → flash), so **inside a DeepSeek session every "Claude" subagent is actually DeepSeek.** Reviews and Claude subagents run only from normal `claude` sessions.
- **Code leaves the machine to DeepSeek.** Never for the exchange (money core and sellable IP): its repo carries `.no-deepseek` and the script refuses, except for the lanes its committed `.deepseek-lanes` names, each under its decision (exchange D-161). Never admin screens (they resolve, void and reissue questions; m1.1 O2). Never production data (domain rule 7).
- Env vars follow DeepSeek's official Claude Code guide, including `CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432`. Effort defaults to `max`, as in the guide (founder 2026-10-06), in both the dispatcher and `templates/deepseek.sh`; `high` stays available (`dispatch-deepseek` with `high` as its second argument, `DS_EFFORT=high deepseek`). Shell profiles source the template instead of copying it, so the interactive launcher cannot drift from the dispatcher.
- Lanes run with WebSearch/WebFetch disabled (DeepSeek's web search costs extra tokens and widens prompt-injection surface). The `claude-opus*` → `deepseek-v4-pro` mapping is billed at Pro price; lanes force subagents to `deepseek-flash`.
- Keep a small prepaid balance and a spend alert; a leaked key can only burn the balance. Verify at bootstrap: inside a `deepseek` session, `/status` shows the DeepSeek base URL; in a normal session it doesn't.
